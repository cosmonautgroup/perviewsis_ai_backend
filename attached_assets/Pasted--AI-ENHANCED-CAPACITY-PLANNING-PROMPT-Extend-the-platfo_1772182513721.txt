

📊 AI‑ENHANCED CAPACITY PLANNING PROMPT

Extend the platform’s Capacity Planning module so it is not a standalone view — but a deeply correlated, contextual system that surfaces capacity risk with links into incidents, alerts, errors, services, infrastructure nodes, transactions, and business impact.

⸻

⚡ DESIGN PRINCIPLES

✔ Capacity Planning must be predictive, contextual, and actionable
✔ Users must be able to navigate from capacity risk → root cause → remediation
✔ Capacity signals must be correlated with:
	•	Alerts
	•	Errors
	•	Incidents
	•	Services
	•	Servers / Nodes
	•	Business Transactions
	•	Deployments

✔ All links are clickable and drillable

⸻

🧭 USER JOURNEY: CAPACITY PLANNING

⸻

1️⃣ GLOBAL CAPACITY PLANNING DASHBOARD

Route
/capacity-planning

This is the landing page for capacity planning where users see:

📌 Forecast Risk Summary
	•	Probability of saturation (CPU / Memory / Disk / Network)
	•	Forecast windows (24h / 72h / 1 week / 3 months)
	•	Confidence %
	•	Business impact estimate

📌 Top Risk List
List items like:
	•	Service A expected CPU constraint in 12h
	•	Node X memory saturation in 48h
	•	Application Y throughput limitation next 3 days

Each item has:
	•	Risk label
	•	Severity
	•	Confidence
	•	Link: “View Details”
→ /capacity-planning/detail/:riskId

📌 Correlation Map
Visual graph connecting:
	•	Capacity risk
	•	Active/past alerts
	•	Related errors
	•	Incidents
	•	Services
	•	Nodes

Click any node to drill deeper.

⸻

🧠 2️⃣ CAPACITY DETAIL PAGE

Route
/capacity-planning/detail/:riskId

This page focuses on one specific capacity risk.

🔹 Header Summary
	•	Risk name: “CPU saturation risk – Service A”
	•	Risk type (CPU / Memory / Disk / Network)
	•	Affected entity (Service / Node / App)
	•	Forecast window
	•	Confidence %
	•	Impact category (Performance / Error / Incident Risk / SLA / Business)

🔹 Forecast Graphs

Interactive time series showing:
	•	Current usage
	•	Forecast usage
	•	Confidence bands
	•	Threshold crossing mark

Graph types:
	•	CPU forecast
	•	Memory forecast
	•	Disk I/O forecast
	•	Network load forecast

Users can toggle time window.

⸻

🔗 CROSS‑MODULE CORRELATION PANELS

Users must be able to go from capacity risk to related items:

⸻

➤ A) RELATED INCIDENTS

Section: “Incidents likely impacted by this risk”

List with:
	•	Incident ID
	•	Severity
	•	Impacted services
	•	Timestamp of swimlane overlap
	•	Confidence % that they are related

Click → /incidents/:incidentId

AI Tip:
“Historical incidents with CPU saturation showed recurrence 60% within same forecast window.”

⸻

➤ B) RELATED ALERTS

Section: “Capacity and threshold alerts”

Show:
	•	Alert name
	•	Source (AppDynamics / Dynatrace / OTel)
	•	Severity
	•	Metric breached
	•	Time
	•	Link → /alerts/:alertId

⸻

➤ C) RELATED ERRORS

Section: “Errors correlated to resource stress”

List:
	•	Error cluster
	•	Frequency trend
	•	Affected service
	•	Time range overlap
	•	Severity
	•	Confidence

Click → /errors/:errorId

AI Tip:
“Network timeout errors spiked concurrently with CPU climbs > 75%.”

⸻

➤ D) IMPACTED TRANSACTIONS

Section: “Business transactions affected by capacity risk”

Metrics:
	•	Transaction name
	•	Response time trend
	•	Error % trend
	•	Impact score (business KPI)
	•	Link → /transactions/:transactionId

⸻

➤ E) SERVICES & NODES

Show two subpanels:

Service Panel
	•	Service name
	•	Resource trend
	•	Forecast risk
	•	Link → /applications/:appId/services/:serviceId/capacity

Node Panel
	•	Node name
	•	Current utilization
	•	Forecast risk
	•	Link → /nodes/:nodeId/capacity

AI Tip:
“For Node DB‑X, memory forecast crosses threshold in next 36 hours with 78% confidence.”

🔁 SMART NAVIGATION & BI‑DIRECTIONAL LINKS

	•	Incident → Capacity risk

	•	Service / Node → Capacity detail

Make navigation bidirectional:

Example:
	•	From /incidents/:incidentId
→ “Capacity risks affecting this incident”
→ Click → capacity detail
	•	From /alerts/:alertId
→ “Capacity risks with correlated alert pattern”
→ Click → capacity detail
	•	From /errors/:errorId
→ “Forecasted saturation tied to this error cluster”
→ Click → capacity detail
